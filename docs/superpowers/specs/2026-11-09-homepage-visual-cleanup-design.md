# Доработка главной «Подгорой»: визуальный порядок и one-page навигация

## Замысел

Привести существующий сайт в аккуратное, законченное состояние без редизайна с нуля и без шаблонного «отельного» лендинга. Для посетителя основная навигация становится естественной прокруткой одной главной страницы. В коде содержимое разделяется на независимые компоненты секций.

## Цели

- Исправить читаемость светлой и тёмной тем, контраст текста, кнопок и поверхностей.
- Собрать главную из последовательных блоков: дом, новости, бронирование, Переславль, контакты.
- Оставить эти блоки отдельными компонентами, не заставляя посетителя переходить между страницами.
- Связать navbar с якорями, плавной прокруткой, hash в URL и активным пунктом текущей секции.
- Сохранить текущие тексты и фотографии, улучшив их компоновку, размеры и ритм.
- Сделать рабочие CTA вместо декоративных кнопок.
- Убрать видимые следы разработки и нерабочие элементы навигации.
- Сохранить HomeReserve, Directus и резервный контент Directus.
- Добавить арку только первому слайдеру главной и синхронизировать анимацию тени с изображением.
- Обеспечить удобную мобильную версию и статичный режим при `prefers-reduced-motion`.

## Не входит

- Новые фотографии, стоковые изображения и выдуманные отзывы.
- Полная смена бренда, новый логотип и переписывание существующих текстов.
- Регистрация, авторизация и работа над их страницами.
- Бесконечное повторение контента, зацикливание всей страницы и перехват колеса мыши.
- Тяжёлые scroll-библиотеки и новые шаблонные макеты.
- Деплой и изменение production-окружения.

## Анти-цели

Не должно получиться: одинаковые «hero + карточки» на каждом экране, анимация ради анимации, тёмный текст на тёмном фоне, блокировка прокрутки, дублирование одинакового содержимого по нескольким URL, технические сообщения для посетителей.

## Ограничения

- Next.js 15 App Router, React 19, Tailwind CSS 4, существующие Embla Carousel и Framer Motion.
- Новые зависимости не требуются.
- Локальные секреты HomeReserve и Directus не переносить и не выводить посетителю.
- При отсутствии Directus использовать существующий fallback.
- Работа ведётся в ветке `feat/homepage-visual-cleanup`, затем независимое ревью и MR в GitHub.
- Существующих автотестов в проекте нет; проверка через стандартные lint/build и реальные сценарии в браузере.

## Рассмотренные подходы

### A. Только техническая уборка

Исправить тему, контакты, ссылки и явные ошибки, оставив компоновку без изменений. Быстро, но не решает проблему визуального ритма и навигации.

### B. Уборка и спокойный визуальный порядок — выбран

Дополнительно выровнять типографику, ширины, отступы, изображения, кнопки, мобильные состояния и темы. Сохранить характер текущего сайта без нового шаблона.

### Навигация: гибрид или one-page

Гибрид с краткими блоками и отдельными полноценными страницами отклонён: пользователю нужны не отдельные переходы, а разделение только в коде. Выбрана одна длинная главная из отдельных компонентов. Существующие публичные URL сохраняются перенаправлениями на соответствующие якоря, чтобы старые ссылки не ломались.

## Устройство решения

### Секции и данные

- В `src/app/components/sections/` создаются самостоятельные компоненты для главного представления, новостей, бронирования, Переславля и контактов.
- `src/app/page.tsx` собирает секции и получает контент Переславля через существующий `getPereslavlContent()`. Клиентские обёртки используются только там, где нужны анимации, виджеты или наблюдение за прокруткой.
- `/news`, `/booking`, `/pereslavl`, `/contacts` перенаправляются на `/#news`, `/#booking`, `/#pereslavl`, `/#contacts`.
- `/api/content/pereslavl` и модель Directus не меняются.
- Внешние виджеты получают `title` и отложенную загрузку; по возможности инициализация происходит при приближении секции к viewport.

### Навигация

- Navbar и footer используют якоря главной.
- Прокрутка остаётся естественной, без fullpage.js и обязательного scroll snapping.
- Sticky navbar учитывается через `scroll-margin`, чтобы заголовки секций не скрывались.
- При прокрутке `IntersectionObserver` определяет текущую секцию; hash обновляется без засорения истории на каждый scroll.
- При открытии прямой ссылки с hash выполняется корректная прокрутка после монтирования.
- На мобильном предусмотрено компактное меню с клавиатурным управлением и закрытием после выбора секции.
- Вход и регистрация только комментируются в navbar; их код не удаляется.

### Визуальная система

- Сохраняются текущий характер и Nunito. Настраиваются размеры заголовков, длина строк, межстрочные интервалы, ширины контейнеров, отступы и соотношения сторон фотографий.
- Цвета, фон, приглушённый текст, границы и кнопки задаются согласованными токенами для light/dark.
- Тёмная тема получает явные читаемые цвета текста и поверхностей; не полагается на случайные наследования.
- Первый слайдер получает арочную форму. Остальные изображения остаются спокойными и не копируют декоративный приём без необходимости.
- Используются только существующие фотографии проекта; повтор одного набора во всех секциях сокращается за счёт доступных кадров.

### Контент и CTA

- Везде используются только: «Подгорая ул., 32, Переславль-Залесский, Ярославская обл., 152024», `podgoroy.pz@gmail.com`, `+7 909 997 55 97` и `tel:+79099975597`.
- «Забронировать» ведёт к `#booking`; «Подробнее» ведёт к следующему содержательному блоку.
- Из footer удаляются шаблонные ссылки и `[В разработке]`. Неизвестные социальные ссылки не выдумываются.
- При отсутствии токена HomeReserve показывается понятный резервный сценарий с телефоном, без красного технического сообщения.

### Анимация и доступность

- Тень и изображение больше не запускаются независимыми таймингами: единая родительская последовательность синхронизирует появление, поэтому тень не обгоняет фотографию.
- Анимируются преимущественно `opacity` и `transform`.
- При `prefers-reduced-motion` входные и autoplay-анимации отключаются, контент сразу виден.
- У автопроигрывания слайдера есть видимая пауза; фокус, подписи изображений и клавиатурная навигация сохраняются.

## Уточнения после независимой проверки описания

- Арка задаётся контейнеру всего первого слайдера, поэтому при смене фотографий форма не меняется и не вызывает скачков тени или компоновки.
- Новости остаются существующей Telegram-лентой SociableKit. Iframe помещается в аккуратный контейнер ограниченной высоты, получает `title` и `loading="lazy"`; отдельную статичную ленту или новые карточки новостей не выдумываем.
- Старые адреса получают временные перенаправления 307 на якоря. Постоянную SEO-консолидацию через 308 отдельно не выполняем.
- Социальных ссылок в footer нет, пока не предоставлен настоящий адрес канала. Ссылку на Telegram из идентификатора виджета не угадываем.

## Что остаётся на усмотрение исполнителя

- Точные значения отступов, цветовых токенов и размеров в рамках выбранного спокойного стиля.
- Небольшие вспомогательные компоненты и хуки без изменения согласованной архитектуры.
- Степень отложенной инициализации внешних виджетов без усложнения решения.
- Оставить ли существующие страницы login как недоступные из навигации заглушки — по умолчанию оставить код без изменений.

## Проверка

- `npm run lint` и `npm run build` успешно завершаются.
- В браузере проверяются desktop и mobile, light/dark, reduced motion.
- Navbar прокручивает ко всем секциям, hash и активный пункт обновляются, прямые старые URL ведут к правильным якорям.
- Все CTA работают; контакты и телефонные ссылки совпадают.
- Тень появляется синхронно с изображением; контент не скрыт при reduced motion.
- HomeReserve проверяется в режиме без токена; Directus — в режиме fallback. Работу реальных внешних токенов не заявлять без фактической проверки.
- После полного diff отдельный новый агент проводит ревью. Замечания исправляются, проверки повторяются, затем ветка публикуется и создаётся MR.
